Alpona draws the pattern.

An LLM decides what to show and how to fetch it. A deterministic engine decides how it renders. The interface itself is the model's output.

the tradition

A fixed vocabulary of motifs.
Infinite compositions.

No two alponas are identical; none break the tradition's rules. Layouts, widgets, and queries work the same way here.

the same points, rearranged

The pattern becomes the dashboard.

One sentence in — a layout is chosen, widgets are bound to real SQL, and copy is written. Streamed live, validated end to end.

no code generated

The output is a spec, not code.

Portable. Diffable. Re-parameterizable. Reviewed in a PR and promoted dev → prod — it outlives the conversation that created it.

why it's dependable

AI flexibility. Design-system discipline.

tools that write code

Brilliant demo, fragile Tuesday

Code-generating tools have the AI write novel React every time.

  • Can break at runtime — in front of stakeholders
  • Drifts off your brand and design system
  • Output is one-off code nobody owns or reviews
alpona

On-brand by construction

The model chooses from layouts and widgets your team approved; a deterministic engine renders them.

  • It cannot ship a component you didn't bless
  • Every output is validated before it renders
  • Looks like your product, because it's built from your product
governance

Built to pass review — security's and brand's.

Read-only by construction

AI-written SQL is parsed, gated, and executed under a database role that cannot write — five independent layers between the model and your data.

Every number is auditable

Each chart and each answer carries the exact query that produced it. "Where did this figure come from?" always has an answer.

Dashboards are documents

Each one is a small JSON spec — reviewed in a PR like any change, versioned, and promoted dev → prod. No data inside, ever.

Yours to keep

Apache-2.0, self-hosted, and able to run fully offline on local models. Your data never has to leave your network.

for the architects in the room

Under the hood: the agent proposes, the engine disposes.

Five stages — three model calls, two pure-code gates. The model can only fail in ways the system catches.

i.

Classify

A question routes to an answer; a description routes to a build.

ii.

Plan

Layout chosen, slots assigned. The skeleton streams in under a second.

fast model
iii.

Bind

One validated SQL query per widget, in parallel. Failures self-heal — once, silently.

strong model
iv.

Compose

Slot contracts enforced, grid computed. Pure code; no inference.

code
v.

Copy

Titles and one-line insights written from the actual result rows.
