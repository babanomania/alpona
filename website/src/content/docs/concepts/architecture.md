title: Architecture
description: The agent proposes; the engine disposes.

Alpona splits the work by what each part is actually good at. An LLM decides
**what** to show and **how to fetch it**; a deterministic engine decides **how
it renders**. The model never emits code — its output is a portable,
versioned, data-free `DashboardSpec`.

```
BROWSER  ── rendering engine: interpreter · composer · widget registry · query client
   │ aggregates only
BACKEND  ── agent service (classify · plan · bind · copy · answer)
           query service (AST gate · limits · param binding · cache · self-heal)
           db adapter (postgres · duckdb)
   │
DATABASE ── read-only role, migrated + seeded via the alpona CLI
```

The agent can only fail in ways the system catches: invalid specs are rejected
by schema, illegal SQL by the AST gate, and broken queries are silently
regenerated by the self-heal loop with the database's own error as feedback.
